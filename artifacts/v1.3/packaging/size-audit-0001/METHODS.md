# Read-only historical APK packaging feasibility

This is supporting final-delivery planning while repaired M4D2 policy tests run, not a later runtime milestone implementation, final archive or acceptance claim. Public top-level APKs in versioned m0–m4 build directories are read unchanged. Models, diagnostic exports, caches, temporary trees and private custody are not traversed. No block payload is saved. Each original APK's byte length/SHA256 is recorded, alongside unique fixed-block counts and uncompressed unique-byte totals.64KiB reads are also divided into4KiB blocks. SHA256-addressed duplicate counting is an estimate of a future content-addressed store; it is not a completed reconstruction test or compression measurement.

Measured100 original files total3,989,385,661 bytes. Unique64KiB blocks total208,348,046 bytes; unique4KiB blocks total148,145,038 bytes across36,206 blocks. This makes preserving all original public historical APKs feasible in principle within three≤500MB ZIPs, alongside normal source/reports/final installation files. A later archival implementation can include final installable APKs directly plus a public block store, exact original-path/hash ledger and a safe reconstruction script for historical APKs. It must reconstruct and verify every original byte/hash before final delivery, measure actual ZIP sizes, explain extraction/reconstruction plainly, and use new versioned outputs. This audit implements no such store or reconstruction tool and guarantees no final archive size. Future release APKs/sources/packs/benchmark evidence add bytes.

An initial broad PowerShell recursive inventory encountered access-denied inherited pytest temporary directories and did not change them. The corrected inventory and this script inspect only explicit public build-directory APK files; both independently count100 files and the same total bytes. Original broad error output remains in the tool transcript, not a claimed saved raw evidence file. The scoped measurement does not require relaxing old temporary-directory ACLs or reading private paths. Model weights/diagnostic exports/private seeds/keystores/custody remain excluded under the owner's instructions; their permitted public acquisition/build/hash records belong in final delivery. No private-material hashes are created.
