## Exact selection and preparation

The readers load derived_texts from the same authenticated, privately copied, schema/hash/signature-validated SQLite snapshot as canonical chunks. Canonical text, language and SHA256 remain distinct from generator text. English primary BCP47 tags en and en-* use canonical text directly, even when derived rows exist. A non-English canonical chunk requires an English purpose=generator row with method official_translation or human_reviewed_translation. Machine drafts are never generation evidence, including developer mode. Among eligible rows, a unique case-insensitive exact en tag is preferred. Otherwise a unique English regional/script rendering is accepted. No eligible row yields NO_ELIGIBLE_GENERATOR_REPRESENTATION; multiple equally eligible rows yield AMBIGUOUS_GENERATOR_REPRESENTATION. No translation-method preference, machine fallback, automatic translation or invented review is used.

Canonical and rendered UTF-8 hashes are rechecked. Blank rendering/derivation source is invalid; human review requires nonblank reviewer/date and the existing strict date/timestamp parser. Pure representation errors distinguish INVALID_GENERATOR_PROVENANCE and GENERATOR_REPRESENTATION_HASH_MISMATCH. Signed malformed metadata is normally rejected earlier by the existing import validator; pure cases separately test the resolver's defense in depth. Signed provenance is an authenticated publisher assertion, not proof of linguistic equivalence or actual human review.

Each candidate representation is resolved once into an owned immutable DTO before selection. All candidates must have eligible representations, including candidates subsequently omitted by budgeting; this conservative policy rejects rather than silently ignoring an unrepresentable candidate. All trial/final evidence counts and complete-template token counts use the exact same rendering bytes and DTO cache. Canonical/title/locator and rendered text reject reserved <|, <think>, </think> controls. Ordinary XML-like data is escaped losslessly. Canonical citations retain original bytes/language/hash, while selected metadata and accepted sources separately expose the actual nine-field generator representation: text, language, text hash, method, derivation source, reviewer, review date, canonical language and canonical text hash. D3 will separately harden redundancy/atomic selection and full evidence identity freezing.
