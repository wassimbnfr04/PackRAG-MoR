This is delivery planning, not a completed package or v1.3 Definition of Done. Final software delivery follows the in-scope verified runtime, mobile, tooling, evaluation and physical acceptance gates in PLAN.md. The owner's9 October clarification assigns final knowledge-pack content to the owner and authorizes any testing packs; ship test/sample packs and clearly separate their validation from owner final-content licensing/review/gold/calibration acceptance. The owner requests full detailed Markdown documentation and the complete implementation, with model weights and diagnostic exports excluded, their public hashes/acquisition/build instructions included, and three ZIPs no larger than500MB each. Private signing seeds/keystores/custody and their hashes are excluded. The final Markdown must explain final architecture and every implemented increment, source/build/model/template/runtime identities, commands/environment, fixture construction, actual versus synthetic data, observed failures and repairs, deliberate reference migrations, exact test scopes/counts, original versus reformatted/reconstructed evidence, results and their practical limits. It must identify external review and dataset/calibration provenance honestly. Benchmark raw model outputs, where required, receive their own controlled evaluation location; product answers contain only validated final text. No historical output is rewritten to make a new implementation appear successful.

Provide ordinary extractable source, tests, configuration, public trust/keys, required source/test-pack licences, final installable APKs, signed test/sample demonstrators, reports/raw evidence, evaluation manifests, reproduction/build/download instructions and a clear index. Owner final knowledge packs are outside agent-authored deliverables; never relabel sample demonstrators as those final packs. Exclude caches, temporary/generated toolchains and redundant existing delivery ZIPs using an explicit exclusion/reproduction manifest. Every included file and permitted excluded large public artifact receives the appropriate hash/custody treatment; private custody must never be read, copied or hashed. Final source/evidence provenance must be reviewable without opening full model implementations or weights.

Historical originals can be reconstructed exactly from blocks, with clear instructions. The originals remain untouched. No block store/reassembler is implemented by the size audit; this is a proposed final delivery method, not a current preservation guarantee. Choose the simplest measured approach that preserves all requested public bytes within the size constraint.
