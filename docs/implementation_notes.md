# Week 1 implementation notes

The supplied architecture v1.2 is authoritative; the user mission supplies the exact G0 cases and decoding. No architectural substitution is adopted by this spike.

- Primary MoR uses the authors' non-KV-sharing rec3 expert-choice release, official unmodified model code and official sharing transformation. Native Windows imports and deterministic inference worked with explicitly selected eager attention. No WSL migration or FlashAttention equivalence claim was made.
- A broad initial Drive folder filter started downloading a KV-sharing compatibility checkpoint. It was interrupted and the filter corrected to the exact notebook experiment before any inference. The primary checkpoint lives in its own experiment directory; its filename, source file ID, byte count and hash are recorded. The partial compatibility download is never loaded or scored.
- G0 direct scoring credits supported requested facts despite malformed repeated wrappers, so 5/10 direct facts receive credit. Citation compliance, exact abstention and adversarial compliance are independently evaluated. All 25 primary outputs fail the product's syntax validator. This is an initial pretrained instruction-following failure; no SFT was executed.
- The shipped synthetic pack is explicitly UNCALIBRATED and developer-only, as permitted by architecture §12.3. Real Granite embeddings use the pinned official model, CLS pooling and L2 normalization. A 512-token maximum is recorded; all synthetic passages are much shorter. No relevance thresholds were guessed.
- ExecuTorch 1.5 source pins the branch `release/2.14`. The observed branch commit differs from the official PyTorch 2.14 wheel's compiled commit. Wheel-based export results are diagnostics, not fulfillment of the exact pinned exporter/runtime contract. No ADR adopting the substitute was made.
- Android SDK CLI 23 split legacy semicolon package IDs. The installer was repaired to fetch Google's exact repository archives and verify their published checksums. Platform `platforms;android-37.0` implements API 37 and is stored at the SDK platform path expected by Gradle. Global toolchains remain unchanged.
- Android code is a developer interoperability spike, not the production registry/atomic update implementation or Week 2 hybrid retrieval. Its private writable validation copy is deleted; the verified original evidence DB is opened read-only.
- Gradle's large compiler download stalled. A project-local Maven mirror contains the exact Kotlin 2.4.20 compiler, verified against Maven Central's published checksum. No alternate compiler version was adopted. Interrupted and checksum-failed attempts are retained in the logs.
- The selected llama.cpp candidate now provides batch generation through `llama-completion`; its newer `llama-cli` is a chat interface and does not accept `--no-conversation`. The prepared phone harness therefore uses the standard completion executable with the official rendered chat template. This is a source compatibility adjustment within the specified llama.cpp/GGUF backend, not a model or architecture change.
- Physical-phone generation and Android instrumentation cannot run because the user reported the phone unavailable. ADB device inventory confirms no connected device. The overall Week 1 gate must remain incomplete.
- Git line-ending conversion is disabled for this evidence repository: signed raw bytes, frozen G0 hashes and raw logs must survive checkout unchanged. Log whitespace is preserved as emitted by the tools.
- A follow-up inference-validity audit confirms our loop matches Hugging Face `generate()` on three frozen 16-token continuations. Eager/SDPA agree on two, but diverge on G0-A01. The original next-token comparison was too limited to establish backend equivalence. Primary G0 scores remain unchanged descriptions of the eager run; canonical author-stack equivalence remains unproven and broader conclusions are provisional.
