# ADR-005: separately versioned document-backed guide runtime

Status: owner-authorized experiment; promotion blocked until comparative semantic and integrated validation. 2026-10-12.

The owner explicitly approved preserving the literal v1.3 baseline while developing a validated runtime revision for complete repair guides. The baseline has context2048, prefill1536, evidence1200 and generated512 total reasoning/final/terminal tokens. Frozen desktop and physical checks establish that full procedural responses often hit512 and safely reject. Increasing the ceiling alone eliminated some exhaustion but left uncited headings. A lazy final grammar improved syntax yet introduced loops when whitespace/citations were unbounded. Each failed original is retained in its versioned output directory.

Prototype profiles mobile-v1-guides-rc1 through rc6 leave weights, tokenizer/template, retrieval thresholds, selected documents, frozen questions, sampling and original seven-line security role unchanged. The generated ceiling is1024, still clipped by remaining2048 context. Additional generic system instructions and a lazy final grammar are explicitly different from literal v1.3. Grammar triggers on the actual closing-think token using the pinned llama.cpp API; reasoning remains private and counts toward the ceiling. Only supplied selected IDs can be emitted as citations. Final lines have bounded padding and up to four citations. Output validation remains unchanged; no post-generation claim rewrite, citation insertion or evidence mutation is permitted.

Rc5 structurally accepted eight repair questions and four negative states, but manual review blocks promotion: FAN_PARAPHRASE changed opening screw checks into tightening, TUBE_PARAPHRASE reordered removal/deflation, FAN_CONNECTOR added unsupported success assurance. Frozen G0-C02 omitted requested6A; G0-A05 answered an unresolved contradiction rather than abstaining. artifacts/v1.3/m4/chat-and-repair-0001/guide-rc5-semantic-review-0001.json records these limits. Structural acceptance is not factual entailment.

Rc6 tests generic preservation of relevant procedural source wording and order, complete requested values/units, no decorative headings or assurances, and abstention on unresolved contradictory evidence. It first rechecks the affected frozen cases; passing them requires the complete frozen repair and generator/security regressions, manual semantic review, then production API/decoder integration and desktop/Android serialization/output parity, native smoke and measured resource evidence. Failures block dependent promotion. No speculative performance claim or synthetic calibration is a release acceptance.

The original v1.3 runtime files/APKs and all historical experiment directories remain immutable evidence. Production Android still runs its original policy/cap until a revision passes these gates. The approved direction does not authorize declaring arbitrary model prose truthful merely because citations parse. If generic instructions fail, redesign evidence-preserving output admission with an additional explicit ADR and comparative tests before implementation. Final owner knowledge packs remain excluded.
