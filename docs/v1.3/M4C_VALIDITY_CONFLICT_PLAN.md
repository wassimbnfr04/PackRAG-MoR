# M4C validity and conflict implementation

Starts after verified B2 checkpoint a9ceb60. Source paragraphs519,521,532,538,
540 and998 are the frozen contract. C is split into integrated C1 and C2;
neither completes C alone. No runtime/model/decoding optimization is planned.

C1 exposes validity provenance and verifies the existing interval filter.
Preserve all four signed source/chunk bounds. Effective start is the later
nonnull start; effective exclusive end is the earlier nonnull end. Null chunk
bounds inherit source bounds. Null source bounds remain explicitly unknown,
even when a chunk supplies a finite bound. Empty intersections are ineligible.
Jurisdiction is exact when supplied; a null source jurisdiction cannot satisfy
a requested jurisdiction. Repealed/superseded status excludes only explicit
current-law requests; historical requests remain governed by their intervals.
Freshness is advisory and must not substitute for source validity. No date is
invented from release/retrieval time. Query dates are already validated by B2.

C1 acceptance: fixed independently written shared interval/status/jurisdiction
expectations on Python/JVM/Android; signed synthetic pack verifies metadata
survives authenticated loading and is filtered before sparse/dense ranks and
alias ambiguity. Expose original/effective bounds and unknown/inheritance flags
in selected/cited runtime provenance. Retained full Python, both host variants,
security/identifier/tokenizer parity, real desktop/phone LFM smoke and production
policy phone gate pass; restore development and bind inputs/history/results.
Only then proceed to C2. This is not a real legal-source or performance gate.

C2 completes conflict-scoped authority and explicit amendment/supersession/
exception metadata without enabling graph candidate expansion. Reconcile the
conservative B2 alias ambiguity with verified explicit relationships; unrelated
aliases/documents must never acquire a global authority sort. Preserve exception
evidence rather than assuming exceptions erase the underlying provision. Define
the rank convention, unknown/comparability behavior, cycle/conflict handling and
deterministic ties from specification/source-builder evidence before code; any
architecture extension needs an ADR. Acceptance includes signed same-provision,
amendment/supersession/exception, historical/current and unrelated-authority
distractor cases plus all C1/B/security and real desktop/phone E2E gates.

C2 is incremental: C2a first exposes the already authenticated authority rank,
document version, issue date, article and typed relationship metadata through
both actual runtimes' cited source provenance. It changes no authority ordering
or ambiguity rule. A new signed corpus verifies original metadata/nullable
values/edge directions/confidence, query ranks remain unchanged, and actual
desktop/phone smoke plus retained security/regression/policy gates pass before
C2b. This integrated metadata path supplies C2b's inputs. C2b then records the
rank/comparability/scope ADR and implements/tests conflict resolution. Neither
C2a nor code alone completes full C or the product.

Later D must also reconcile paragraph532's highest-ranked nonidentifier relevance
gate after merge; current local per-pack marking is not declared complete against
