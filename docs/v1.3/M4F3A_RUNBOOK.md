## Timing and token interpretation

These are functional test runs. Whole instrumentation-class duration includes fixture work, ownership hashes, any isolated full-size copies, multiple methods and cleanup. Before/after source guards are separate host steps. None of those elapsed times is generation-only latency.

ProductSession.ask starts its monotonic timer after entering its synchronized method. It includes active-pack checking, cold local-asset verification/constructor work when needed, retrieval/admission, generation and final-output validation. It excludes waiting to enter that method, earlier ViewModel queue/session construction and later GUI rendering/metadata refresh. The diagnostic JSON names this session ask wall time explicitly. A cold initialization_ms value aggregates verification, leases and model/runtime initialization; it does not isolate disk time from model construction. Warm initialization_ms=0 means the runtime was already loaded for this call, not zero answer latency. Retained session load metadata in a warm result describes the existing loaded session, not another warm load.
