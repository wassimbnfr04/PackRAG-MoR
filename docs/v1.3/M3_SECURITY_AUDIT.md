The actual importer sequence is precise. Android copies the caller transport into its private stage with a transport bound and fsync, audits ZIP records, verifies raw bounded manifest/signature with Tink, and only then scans/parses/canonicalizes/validates authenticated JSON. Android streams each payload with size and CRC checks and verifies SHA256 of the written file before any data-format interpretation. The desktop importer uses bounded entry reads and verifies length/SHA256 before writing its private payload; it does not claim constant-memory streaming extraction. All declared payloads must match before KDX or SQLite is interpreted.

D3 moves independent KDX magic/version/type/metric/dimension/flags/count/file length/profile hash/finite-value/norm checks ahead of SQLite. Vectors are read row-by-row, with ascending double accumulation matching Android. The signed mapping hash cannot be bound until the disposable DB has supplied validated ordered row IDs, so that check follows DB validation. Nine fresh correctly signed/hash-redeclared fixtures prove bad KDX wins over a simultaneously broken DB, valid KDX reaches the broken-DB rejection, mapping hash rejects after validated rows, and float32 vector norms just inside/outside the tolerance agree across Python/JVM/phone. Synthetic norm changes do not establish faithful embeddings.

DB validation uses a writable disposable copy for integrity_check, foreign_key_check, exact schema/object/type/metadata checks and FTS5 external-content rank1 integrity. The original hash-verified DB is compared before/after and mounted read-only. Source/derived provenance fields are validated structurally; real reviewed translations and gold/calibration remain M5/M6. The app cannot infer that a claimed reviewer actually reviewed a text from signed metadata alone.

Registry recovery is not automatic rollback. An uncommitted renamed directory is cleaned; corrupt installed bytes become untrusted and inactive without selecting an older version. Atomic activation retains the prior version only after durable directory rename and FULL SQLite transaction. Explicit removal/deactivation keeps identity/high-water history. Query snapshots exclude concurrent lifecycle mutation. Controlled fault injection, actual separate-process SIGKILL with three genuine hot journals, owner-registry preservation and physical warning/dialog checks are distinct evidence. They are not physical power-loss or exhaustive crash testing.

The production-policy demo is deliberately instrumentable and Android Debug signed; its app policy rejects uncalibrated/unknown signers, excludes development key assets/crash probe, ignores debug launch routing, uses a separate registry and has no INTERNET permission. It is not the final non-debuggable signed release. Final M8 signing, final pack UI/product acceptance, performance/thermal profiling and the optional airplane demonstration remain separate. Mobile data stays on throughout these owner-authorized tests.

Private-source boundaries apply to result manifests, real desktop-smoke inputs and Android source-at-build-start collection. Private custody, generated build/cache paths and resolved paths outside the workspace are excluded before hashing. The tests use literal non-secret sentinels, never a private publisher seed. Earlier reports are preserved; the actual seed extension had already excluded it from those old reports.
