## Increment B: actual native embedding and tokenizer parity

Implemented the pinned Granite tokenizer from its authenticated tokenizer.json: exact Split regex, ByteLevel byte mapping, added-token behavior, ignore-merges vocabulary lookup and ranked BPE. Implemented actual ONNX CPU inference with int64 input IDs/attention mask, FP32 CLS pooling and L2 normalization, four intra-op threads, one inter-op thread, exact asset hashes and explicit 512-token rejection rather than truncation.

`parity-reference-0001` froze 36 desktop token cases, four actual ONNX vectors and ten actual retrieval/prompt references, including real LFM token IDs. `parity-reference-0002` is a separately hashed derivative adding eight Unicode whitespace cases. Host and phone use the latter 44 token cases. Neither reference generation is itself Android acceptance.

Preserved failures and repairs, in order:

1. ONNX Runtime's dependency manifest inherited INTERNET. `device-embedding-0001` failed the mandatory permission assertion before inference. Main manifest now explicitly removes that permission in all variants. Original dependency manifest is retained in `dependency-manifests`.
2. Shell-owned external model files were inaccessible to the app. `device-embedding-0002` passed permission checks but failed access. Assets now reside in app-private storage; storage permissions were not broadened.
3. Windows text-oriented ADB shell transport truncated ONNX at its first Ctrl-Z byte, byte 11. Hash verification rejected the partial file. A separate exec-in shell-redirection attempt failed due quoting. A binary 0–255 probe verified `adb exec-in run-as ... dd` transport. `private-assets-0003` records successful full-file hashes, restrictive file modes and rename after verification. Prior setup attempts remain preserved.
4. Android rejects JVM UNICODE_CHARACTER_CLASS flags because its regex classes already use Unicode. `device-embedding-0003` failed before inference. Keep the exact tokenizer regex and select platform flags; add the eight Unicode cases to fresh reference 0002.

`build-0005` and `device-embedding-0004` pass all 44 exact token cases and four numeric vectors. Maximum observed phone embedding error is approximately 1.23e-7 versus predeclared 1e-4; all cosine similarities exceed 0.99999. One JUnit instrumentation method contains these assertions. Reported initialization includes file hashing/tokenizer/session setup. Java heap delta is end-minus-start, not peak native memory. Per-case timing is component inference, not end-to-end question latency or release performance acceptance. Full details and exact values remain in raw JSON.

## Increment C: authenticated activation and retrieval

Created security-crypto, kpack-registry and retrieval modules. Tink authenticates bounded raw manifest bytes against 1–8 distinct raw 32-byte pinned keys, requires exactly one verifier, then checks canonical JCS and the signer key ID. Import audits one bounded app-owned transport snapshot; validates portable ZIP paths, case-insensitive duplicates, regular file types, allowed payloads and size limits. Each declared payload is length/hash checked and fsynced. A disposable SQLite copy undergoes integrity/FK/schema/FTS checks; original bytes are checked unchanged. KDX header/profile/mapping, exact dimensions/length, finite FP32 normalized rows are verified. Only then can ActivePack open a read-only DB and map vectors.

Registry persists first activation, rejects replacement and reauthenticates its stored transport into a separate checked snapshot on reopening. This is a deliberately bounded M2 lifecycle; full atomic update/rollback/crash recovery belongs to M3. It is not a production lifecycle acceptance claim.

Retrieval performs validity/jurisdiction/current-law eligibility before retaining top-k results, Unicode-boundary aliases, actual SQLite FTS5 BM25 and actual dot products, fixed 24/24 candidate caps, RRF60, 16 local/32 merged caps and content-identity dedup with origins. Synthetic UNCALIBRATED packs admit exact eligible aliases only; no semantic thresholds are invented.

`build-0006` failed one test because its expected pack ID used `developer` instead of the fixture's actual `development`; cryptographic verification succeeded. The assertion was corrected and `build-0007` passed four host methods: tokenizer, raw-signature/bounded-trust cases, portable path cases and exclusive temporal intersection cases. Source/config hashes are captured at build start from this run onward. XML for an unchanged UP-TO-DATE module retains its original execution timestamp; the Gradle log distinguishes rerun tasks. Failed-run XML is retained.

`device-retrieval-0001` passed ten actual-phone cases: exact candidate order, sparse/dense rank, RRF and cosine tolerance versus frozen desktop reference. The phone computes its own query embeddings and searches its own SQLite/KDX; it does not load saved answers or desktop-ranked candidates. It also passes unknown-key, modified signature, modified KDX and uncalibrated-production rejection, duplicate activation rejection, unrelated-query relevance rejection, original DB/archive unchanged checks and authenticated registry reopening. Structured output records the four import negatives and ten parity cases; other assertions are in the instrumentation source/JUnit stream. This is component/adjacent integration, not an Android generation benchmark.

## Increment D and full M2 acceptance

Implemented: exact pinned llama.cpp JNI CPU bridge, shared lifetime-safe handles, persistent model/context, synchronized generation and CPU abort callback. Portable armv8-a Release compilation disables GGML_NATIVE/OpenMP/KleidiAI/LLAMAFILE; batch256/ubatch128, one sequence, four threads, context2048, no offload, FlashAttention disabled. Actual GGUF architecture/file type and full-inference parameter count are checked. Kotlin verifies full GGUF/template SHA before load. Native UTF-8 byte arrays avoid modified-UTF8 corruption. Context/recurrent state is cleared for every generation; greedy decoding remains the frozen temperature-zero behavior. Full actual emitted IDs include terminal EOG if sampled; the output text omits terminal EOG. Model token timing includes hidden reasoning and is not visible-answer latency. Buffered output is structurally validated before UI display; private buffers are never logged or written to evidence.

```powershell

.venv-pack/Scripts/python.exe -X utf8 -m scripts.v13_test_android --serial R3CT908DHHR --build artifacts/v1.3/m2/NEW-BUILD --run artifacts/v1.3/m2/NEW-PHONE --class-name org.packrag.product.PackRetrievalParityTest --result-file m2-pack-retrieval-parity.json
```

Generator weights are not packaged in APKs. Model installation is separate, hash checked and reproducible through `scripts/v13_install_phone_assets.py`.
