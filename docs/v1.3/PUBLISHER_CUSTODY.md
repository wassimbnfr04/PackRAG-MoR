# Project demonstrator publisher custody

This is a project-owned transport signer, not the official publisher of source material. Its signature establishes exact transport integrity and signer possession. It does not establish source truth, legal interpretation, genuine translation review or calibrated retrieval quality. Those are separate release gates.

The approved public store is product/config/release-trust.json; its exact bytes are compiled as app/src/main/assets/release-trust.json. One through eight unique public keys are supported. Packs cannot introduce a key. BuildConfig.ALLOW_DEVELOPMENT_PACKS is true only in the development build; release policy uses only the approved store and rejects UNCALIBRATED manifests. Production and development registries are separate. The current production-core tests in a DEBUG artifact are not actual release build acceptance.

The owner's private seed is product/.private/demo-publisher.seed. The directory has Windows inheritance disabled, with full control restricted to the current owner and SYSTEM. The file is ignored by product/.gitignore and excluded from APK assets, version control, reports and delivery archives. Never print its bytes, attach it, hash it into public metadata, or copy it into fixture assets. Only signing code reads it. Public artifacts can be verified without it. Losing it prevents signing updates under this identity; do not silently replace it or claim another signer is equivalent.

For a clean build, the shipped public JSON is sufficient. To create an independent publisher, use a separately controlled private directory with equivalent access restrictions, generate its own seed, and deliberately review/update the application-owned public configuration and all bound release fixtures. Do not run setup expecting it to recreate the existing private key. scripts/v13_publisher_setup.py resumes a matching local seed or creates a new one only when absent, refuses a different existing public configuration, and records only public setup metadata in a new versioned run. Key rotation requires an explicit reviewed configuration change and regenerated acceptance evidence.

Before packaging, exclude every directory named .private and private keys/keystores regardless of extension. A mere filename-extension filter is insufficient. Model weights and large diagnostic exports are also excluded under the owner's instruction, with public hashes and setup/build instructions supplied instead. Check the final archive entry list and verify that only public publisher metadata remains. Never claim that an implementation archive enables signing as the existing publisher.

The release-trust-fixtures-0001 positive pack is reserved org.packrag.test.release-policy version0.0.1+fixture, explicitly named SYNTHETIC TRUST TEST — NOT RELEASE CALIBRATION. Its calibration numbers are only schema fixtures. It must never be distributed as either release demonstrator or used as measured PackBench evidence. The public-store eight-key case tests the format limit and does not approve those fixture keys for the product.
