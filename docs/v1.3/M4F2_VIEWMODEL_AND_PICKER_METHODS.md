# M4F2 ViewModel and system-picker iteration

Implementation0067 follows passing versioned actual four-slot import/native0066, importing-subprocess recovery0065 and fault/API0063 iterations. It adds no model/pin/trust/native parameter or product permission. Build0067 host73 and APK/source contracts passed; physical ViewModel and actual picker/UI results are separate gates. This document describes implementation and acceptance methods, not a declaration that F2/M4/product is complete.

The production Activity has a second `OpenDocument` launcher, dedicated to the selected fixed asset slot. A primitive enum name is stored with `rememberSaveable`, including while the external picker is open. The callback clears that selection and dispatches only a non-null granted URI with a valid slot to `PackRagViewModel.importLocalAsset`. A cancelled picker dispatches no operation. The slot determines the fixed private destination and size/hash pin; provider filenames/MIME labels do not choose a model, path or pin. URI permissions are used for this one copy; no persisted URI or automatic reopening is introduced. Each of the four local-asset rows has its own chooser, disabled during an active operation. No download, broad storage or network permission is added.

The ViewModel retains the existing cancel/join of the previous job and shared action mutex. Import success/error/cancel uses the existing preserve-result action path. Completed answer, immutable captured trace, submitted query and completion UUID retain the same references/identity while local files change; new questions and ordinary pack changes retain their previous result-clearing behavior. Generic preserve-result failure recovery previously lost those fields;0067 repairs that branch as well, while closing/reopening the session and refreshing registry labels. Typed importer failures report a safe code and whether cleanup is pending. Verification observations are updated from the real session; the selected successful slot is VERIFIED and other cached slot checks become UNCHECKED. Four-file rechecking is still independent, and native loading verifies again.

Progress is observed bytes and actual stage, filtered by the current action epoch and fixed slot. It is not an estimate of how many bytes the provider claims to hold. Epoch is volatile for the I/O callback, and StateFlow updates are atomic. The UI shows copied/expected bytes, stage and a bounded copy fraction. Syncing, verification and commit remain separate text phases after copying reaches100%;100% copied is not presented as a successful installation. A completed operation removes its active progress row and reports actual outcome. Postcommit directory-sync/cleanup uncertainty is shown as a warning; it does not pretend the old bytes were restored.

Import cancellation marks a request, dispatches the session/source cancellation and keeps the action alive until real cleanup or an already completed commit returns. It does not cancel the job and immediately claim rollback. A cancellation before the session captures its own ticket is also checked before dispatch and at the initial COPY event before the caller descriptor opens. Late commit may correctly produce an installed-and-verified result. Other actions still wait for the previous action to finish. A cooperative provider is required for the tested dispatch/completion bounds; this does not claim arbitrary Binder/filesystem/provider IPC can always be interrupted within a fixed time.

`LocalAssetImportViewModelDeviceTest` is a background physical test with no Activity or external picker. It uses a test-only Application subclass overriding filesDir/cacheDir into a new owned UUID root; production has no alternate storage-root switch. It imports the four full actual assets through the existing separate-UID provider, activates the exact signed synthetic walking pack and generates a real first answer through the production ViewModel. It then requires identical answer/trace/submission/completion UUID and old final-file pin after wrong-hash rejection, generic non-content-URI recovery, observed128-byte partial blocked-read cancellation, transported blocked-open cancellation, successful template import and four-file rechecking. It checks main-thread cancellation dispatch below1000ms and operation completion within15s for those cooperative fixtures, recording milliseconds separately from copied bytes. It finally generates a real cold accepted answer with a new completion UUID, required initialization and canonical source pin. Eight ordered controls, original main/progress JSON, source4/owner50 hashes and frozen source/APK identity must pass before later UI progression. Test cleanup waits for model/session closure, deletes only its validated owned root without following links, and never traverses private custody.

Actual Android system-picker selection and cancellation, saveable slot across recreation, displayed progress/cancel behavior, return-to-answer/canonical-source navigation and viewport/accessibility inspection remain required separately. Explicit shell/DUMP receiver grants in background tests are not substituted for system-picker proof. A fresh untouched foreground window is requested and announced only after the prepared UI test and preceding background validation are ready. Mobile data remains on. These tests use synthetic packs only; final domain knowledge packs, real review/calibration/gold and final release/performance acceptance are not inferred.
