The content-provider transport harness belongs only to the instrumentation APK. Any harness-only narrow URI grants are identified as such; they do not replace the separate actual system-picker acceptance. No product INTERNET, broad storage, root, CPU/governor/affinity or RAM privilege is added. Provider filenames/MIME/announced sizes are not destination or verification authority. Product paths and four existing pins remain fixed; smaller independently pinned specimens are unit-test-only.

Import/read leases enforce the existing private-file/model lifecycle invariant inside ProductSession. A busy foreign reader is a deterministic pre-write rejection, not an excuse to replace a mapped file or silently change the model/profile. This is an implementation decision, with actual multi-session acceptance required; it adds no retrieval/model/trust subsystem.

Platform references checked11 October2026: [ContentResolver](https://developer.android.com/reference/android/content/ContentResolver) supports cancellable descriptor opening and requires the caller to close descriptors; [DocumentsProvider](https://developer.android.com/reference/android/provider/DocumentsProvider) uses system-issued narrow URI grants for selected documents; [Files.move](https://developer.android.com/reference/java/nio/file/Files) specifies atomic-move failure when unsupported and implementation-specific replacement of an existing target. Android replacement behavior must be tested physically. No non-atomic fallback is accepted.
