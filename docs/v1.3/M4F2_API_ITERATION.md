# M4F2 first transport iteration — methods and limits

This is an iteration inside F2, not its completion. Base F1 checkpoint is ccc14de708bf2d46d2791875a8cca9344fc25f48. `asset-import-gate-0001/before.json` records the actual accepted F1/public historical/input and known50 phone-file hashes before changes. Every new build and device attempt uses a fresh location; failed outputs stay unchanged. Final knowledge content remains owner supplied. The phone's mobile data stays on; product APK has no INTERNET permission.

The four production slot paths, byte lengths and SHA256 pins are unchanged. `LocalAssetImporter` selects them by `LocalAssetSlot`; document names, paths, MIME types and metadata sizes never select a destination or pin. Its smaller independently pinned `hello` specimen exists only in eight host boundary methods. Those tests do not establish Android directory sync, URI permission, real model or power-loss behavior.

`LocalAssetLeases` keeps short synchronized process-local reader/writer tokens keyed by normalized absolute private model root. Read tokens cover warm generator/encoder lifetimes and verification. A writer fails with LOCAL_ASSETS_BUSY while any foreign session holds a read token, before opening input or writing staging. Closing tokens is idempotent. These are fail-fast leases, not a waiting lock held across different session monitors. ProductSession closes its own generator/encoder before import; it retains a read token if model closure fails. Cross-process exclusivity is not claimed by a process-local token; the shipping app currently runs these sessions in its one product process.

`LocalAssetUriSource` accepts content scheme only and opens one cancellable AssetFileDescriptor through the actual ContentResolver. It uses createInputStream to respect asset-descriptor slices and closes both stream and descriptor. External URI data is not persisted or reopened after verification. Its first cancellation implementation marks the operation cancelled and asynchronously closes the stream and cancels descriptor opening; generic provider cooperation/blocked IPC and cancellation fault controls remain to be physically tested and hardened. No claim of bounded cancellation for an uncooperative provider is made by this initial iteration.

The importer acquires an exclusive root token, checks private root/parent/final file types without following links, reconciles only its flat reserved `.asset-import-v1` namespace after validating exact ownership-marker magic, known slot/UUID `.part` names, regular nonsymlink types and bounded lengths. Unknown entries cause rejection before deletion; legacy partials elsewhere are untouched. Reconciliation is explicit and pre-import in this iteration; actual startup/restart reconciliation is still pending.

It creates a new namespace marker and exclusively creates a slot/UUID stage, copies at most the selected byte limit with64KiB buffer, handles short/zero reads, counts actual received bytes and closes the source once. Exact length is required; file-channel force completes before a separate staged-file read-back SHA256/length check. Directory sync precedes the atomic move. Final parents are validated/created only for fixed slot components. ATOMIC_MOVE has no non-atomic fallback. Actual Android replacement must pass on-device; Windows host success cannot substitute.

Progress reports selected slot, COPYING, SYNCING, VERIFYING, COMMITTING or COMMITTED and observed copied byte counts. Callback failures are swallowed so an observer cannot undo or misreport a completed rename. Pre-commit cancellation/rejection leaves the preceding final bytes intact. The returned result includes installed size/SHA256/UTC timestamp and a separate final-directory-synced boolean; failure of directory sync after rename does not pretend that the old bytes survived. Best-effort exact owned cleanup currently lacks a separately exposed cleanup outcome; fault/restart hardening is required before F2 acceptance. No power-loss durability is inferred from ordinary process restart.

ProductSession invalidates last-check statuses on import, closes its own native models, invokes the same private importer under BlockingIo, marks only the imported slot verified after success, and leaves other slots unchecked until normal independent verification. The next cold ask still requires all four pinned files before actual encoder/generator construction, then normal verified-pack retrieval, evidence admission/selection, LFM2.5 generation, reasoning removal and output/citation validation.

The first device harness is deliberately a separate-UID, instrumentation-APK-only ContentProvider serving the exact5443-byte public official template copied read-only from its known pinned phone path. APK custody binds its size/SHA256 to the accepted template. An explicit test-only receiver protected by android.permission.DUMP issues a narrow template read grant to org.packrag.product when invoked by shell. It provides no product privilege or broad storage access. Provider open/close/error counts and actual UID are queried independently by the test; importer never uses these audit queries as input authority. This transport is not the system document picker, which remains a separate mandatory F2 gate.

The test uses one newly owned private root and copies all four actual models under a free-space guard (sum2009206667bytes plus64MiB). It activates the exact versioned synthetic signed fixture, checks an actual cold74°C/[S1] answer and canonical-source SHA256, verifies a second session cannot import while the first holds real warm mappings, imports the template through the first session, checks real descriptor one-open/one-close/error counts, bytes/hash/commit/cleanup/model-release/status/progress, and asks again through the real cold native path. It closes sessions before deleting only its owned root without following links. The50 public owner paths, including original models and legacy partials/default registries, are independently guarded before/after. Their known hash map is not a new complete phone-directory enumeration.

Build0058 fails at Kotlin compilation: Android public OsConstants has no O_DIRECTORY member. Its exact ten changed Android inputs, log and failed result are captured. Existing62 host XML in that failed build are retained inputs/results, not a new successful run of the eight importer methods. The correction uses public O_RDONLY|O_NOFOLLOW|O_CLOEXEC, actual descriptor fstat/S_ISDIR and fsync/finally-close, following the existing registry directory-sync pattern. [Android Os](https://developer.android.com/reference/android/system/Os) and [OsConstants](https://developer.android.com/reference/android/system/OsConstants) document those public calls.

Instrumentation setup revoking a pre-start grant is a hypothesis; no grant-lifecycle trace establishes causality. No actual import/native PASS is claimed for that failed attempt. All50 known owner hashes match afterward. The build log distinguishes executed app test tasks from UP-TO-DATE module XML. Each successful iteration capture verifies exact frozen current source, public trust pin, unchanged native binary pin, product absence of INTERNET and harness components, test-only fixture/provider/receiver presence and APK CRC. Save the actual device JSON bytes before any APK switch. First iteration success will still leave all-slot imports, fault/cancel/restart/system-picker/ViewModel/UI/policy/adjacent/closure/checkpoint acceptance pending; it does not establish full M4, release signing, final domain expertise, licensing/calibration approval, gold accuracy or M8 performance.
